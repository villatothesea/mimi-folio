# 米素单篇路由——实施计划（配合米米 Agent 改造阶段 5）

> 背景：米米主仓改造说明书 `Mimi-tauri/docs/Agent机制改造-说明书与分阶段计划.md` §6。
> 米米要"掌握米素全部操作"：能搜库、能引用、能把用户直接带到那篇那处。
> 本计划是**米素仓侧**的全部改动；米米侧（daemon 工具、ShowInFolio、壳拼 URL）由米米战役负责。

## 0. 范围与纪律

- **纯前端改动，无 API 变更**——不触发本仓"types.ts → api.ts → 双 Host → folio.rs 镜像"的同步纪律。
- 独立可发、不阻塞米米主线：米米侧在米素未带路由时降级为打开米素首页。
- 顺手原则：锚点滚动复用 `src/ui/toc.ts` 现成的 `headingEls()` + `scrollIntoView`（目录点击已在用）。

## 1. URL 契约

入口 URL 追加两个可选 query 参数，与现有 `token` / `host` 共存：

```
{入口}?token=…&host=mimi&doc=<vault内相对路径>&anchor=<标题文本>
```

- `doc`：以 vault 根为基准的相对路径，**与 `/folio/v1/list` 返回的 path 字段同构**（encodeURIComponent 编码）。
- `anchor`：目标标题的文本（encodeURIComponent），匹配策略为**归一化空白后的子串匹配**，容忍模型转述与原文的轻微差异。
- 参数在刷新后保留（刷新仍落原位）；不带参数 = 现状行为，零影响。

## 2. 行为规格

1. **doc 定位**：启动序列拿到文档清单后，拿 `doc` 参数在清单里精确匹配（先原样，再归一化 `/`↔`\`）。**清单匹配即安全边界**——不直接 join 路径，天然防穿越。匹配不到 → 静默落到默认打开流程（不弹错、不空白）。
2. **anchor 定位**（仅 `notes/` 类 md 文档）：等 Muya 渲染完成再滚（toc.ts 已处理过同类时序，照搬）；`headingEls()` 文本归一化子串匹配 → `scrollIntoView({ block: 'start' })`；匹配不到 → 滚到 `#doc-head`（文档顶部）。
3. **`.html` 文档**：走 iframe 预览时，把 anchor 转成 iframe src 的 `#fragment`（浏览器原生锚点；html 内无对应 id 则忽略）。
4. **memos**：首版只定位到该条 memo 所在视图（月历选到对应日）；不做卡片级滚动——若实现成本高，退化为只打开当天。
5. **双 Host**：独立模式（无 token、无 daemon）也要能解析 `doc`/`anchor`（本地 dev 预览可用）。

## 3. 测试（照 `toc.test.ts` 的路数）

- 参数解析：有/无 doc、无 anchor、坏编码。
- doc 匹配：原样命中、分隔符归一化命中、miss 退化。
- anchor 匹配：精确命中、子串命中、空白归一化命中、miss 退化到顶部。

## 4. 验收

- 手工：带 `doc`+`anchor` 打开直接落位到那篇那处；坏参数不炸、行为同现状。
- 联调（米米侧阶段 5 一起）：对话里说"找昨天那篇关于色卡的笔记"→ 米米检索定位 → 产物卡/引用处点开 → 浏览器直达米素该篇该标题。
